## Live web-deployable apps (the only ones we can Dockerize without inventing URLs)

These are the eight `yes-pure-web` and two `yes-with-adaptation` repos. None of them currently sit at the URL configured in `full-28-apps.json` — every one of them requires the catalogue's `source.url` to be repointed to the candidate repo first.

Pure web (HTTP server, long-running):

- **iptv-restream** — `antebrl/IPTV-Restream` — TypeScript/JavaScript — `docker compose up -d` — port **80** (configurable via `docker-compose.yml`).
- **iptv-stream** — `RickyRLD/iptv-player` — Python — `python iptv_player.py` — port **8765**.
- **nuvioweb** — `NuvioMedia/NuvioWeb` — JavaScript (Stremio-addon web client) — `npm run build && serve dist/` — port **8080**.
- **smart-iptv-web** — `Web-IPTV/iptv` — HTML/JS + Node — `python3 -m http.server 8080` plus EPG server on **3001** — port **8080**.
- **stalker-ui** — `kidpoleon/stalkerhek` — Go — `docker run` (binary on Dockerfile) — Web UI at port **4400** (`/dashboard`).
- **tvapp** — `TheBinaryNinja/tvapp2` — JavaScript — `docker compose up -d` (multi-arch image already published) — port **4124**.
- **wizju-iptv-player** — `j2jstudio/wizju-iptv-player` — TypeScript + Vue 3 + Vite — `npm run dev` for live; `npm run build && serve dist/` for prod — port **5173**.
- **xstream-player** — `jandersonss/xstream-player` — TypeScript + Next.js — `docker run -p 3000:3000 jandersonss/xstream-player:latest` — port **3000**.

Web-deployable with adaptation (desktop-first repos that ship a documented web/PWA path):

- **extreme-infinitv** — `infinitel8p/Extreme-InfiniTV` — Tauri/Astro app with `pnpm build` producing a static `dist/`. README explicitly: *"Web preview - Build with `pnpm build` and serve `dist/` (no auto-update, no native features)."* Behind nginx as static assets.
- **iptvnator** — `4gray/iptvnator` — Electron/Angular app with a documented self-hosted PWA Docker image. README: *"The Docker setup builds the Angular PWA and the monorepo web backend into one image."* Dockerfile lives in `docker/`.

## Notes for downstream deploy work

- Per CONTRACT.md §2.1, only the rows in **Live web-deployable apps** above are eligible for Dockerfile/compose authoring without amending the schema first.
- The 12 desktop-only / Tizen / Windows-installer rows must not be turned into "web" deployments by guesswork — they have no web mode in their READMEs. They should either be dropped from the VPS deployment plan or, for catalogue entries where the catalogue's `launch.kind` is already `tauri-dev`/`exe-shortcut`/`tizen-deploy`, left as launcher-only entries.
- Static-playlist rows (`free-tv-iptv`, `iptv`) deploy as static asset serving only — they're not HTTP services, but their generated `.m3u`/`.m3u8` artefacts can be checked into a static-file container if needed.
- The catalogue's `source.url` for every "yes-pure-web" candidate row needs the URL change applied before deploy: each currently points at `github.com/example/...` which is a hard 404.
