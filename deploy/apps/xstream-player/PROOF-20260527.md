# xstream-player DaveAI Proof - 2026-05-27

## Scope

Fixed the user-reported xstream-player playback and visual-card issues on the live
`xstream-player.daveai.tech` deployment.

## Changes

- Replaced broken/placeholder channel, movie, and series artwork with a local
  fallback card component when provider images are missing, tiny, or known
  placeholder assets.
- Added a server-side SVG fallback in `/api/provider-vault/image` for
  safe-but-dead upstream artwork so browser image loads return a usable card
  graphic instead of a broken `404`.
- Kept all provider media/image URLs behind the DaveTV provider vault so Apollo
  Group TV and XtremeHD credentials are not exposed in browser URLs.
- Added `/api/provider-vault/transcode-hls` for browser-safe HLS fallback when a
  VOD/series stream needs conversion.
- Blocked non-video upstream bodies from being sent to `<video>` as if they were
  media. Provider HTML/JSON failures now return a controlled `502` proxy result.
- Updated the player error path so failed/dead streams show:
  `This provider stream is unavailable right now. Try another title, episode, or provider.`
  instead of raw Chromium demuxer or `MEDIA_ELEMENT_ERROR` messages.
- Converted the TV debug error boundary strings to English and added a one-time
  chunk reload path for stale-browser chunk errors.
- Waited for full catalog sync in visual QA before judging card population.
